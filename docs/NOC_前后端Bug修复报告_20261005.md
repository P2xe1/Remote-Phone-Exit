## 1. 前端问题

### 1.1 流水线卡「状态未上报」与健康卡「在线」自相矛盾

- **现象**：同一时刻，链路卡片显示灰色「状态未上报」，而下方健康卡显示绿色「在线」。
- **根因**：手机上报的 `telemetry.xrayLive` 是**数字 1/0**；流水线卡用 `xr === true` 判断（只认布尔），健康卡已做 `1 / '1'` 兼容 → 同一字段两处口径不一致。
- **修复**：流水线卡判断改为 `xr === true || xr === 1 || xr === '1'`（离线同理兼容 `0 / '0'`）。
- **验证**：线上同屏显示一致（两处均为「Xray 在线」）。

### 1.2 节点矩阵状态栏永远停在「等待探测结果」

- **现象**：55 个节点全部测完（旁注「已测 55」），状态栏仍是「● 节点清单已装载 · 等待探测结果」。
- **根因**：该文案是**静态 HTML**，全文件仅出现一次，没有任何 JS 更新逻辑。
- **修复**：改为中性文案「● 节点矩阵 · 手机端顺序探测」，不再暗示"尚未完成"。

### 1.3 右上角「X 秒前数据」虚增，与顶栏「数据 X 秒前」矛盾

- **现象**：默认 1 分钟采集模式下，右上角标签会从 0 一路涨到 60 秒；实测同时出现「数据 1 秒前」与「56秒前数据」。
- **根因**：该标签用"上次轮询基准 + 本地累加"计算，而轮询间隔是 60 秒；实际数据由手机每 6 秒推送，真实年龄 ≤ 6 秒。
- **修复**：优先使用实时推送的 `liveAgeS +（当前时间 − 上次推送时间）`，轮询基准仅作兜底。
- **验证**：实测右上角「2 秒前数据」与顶栏「数据 0 秒前」一致。

### 1.4 节点「数据陈旧」阈值与探测周期不匹配

- **现象**：一片节点变黄显示「数据陈旧」（实测 55 个中 21 个），与「已测 55」同屏，看起来像故障。
- **根因**：阈值写死 600 秒；而手机端逐节点探测一轮耗时在 **7~17 分钟**之间波动（受网络影响），队尾节点必然超过 600 秒。
- **修复**：改为**按轮次**判定：
  - 轮长 = 相邻节点实测间隔中位数 × 节点总数（夹在 300~3600 秒之间，动态计算）
  - ≤ 1 轮 = 绿「连通」；≤ 2 轮 = 黄「数据陈旧」；> 2 轮 = 灰「未探测」
  - **只有手机真正探到失败/超时（ok=false）才显示红色「不通」**
- **验证**：55 个节点恢复全绿；已知失效节点仍正确显示红色「不通」。

### 1.5 4 处引用了不存在的 DOM id（死代码）

- **现象**：表面无异常（写入静默失败）。
- **根因**：改版删除 UI 块后，写入代码保留：`riskBadge` / `hwBattery` / `hwBatteryStatus` / `hwSockets`。
- **修复**：删除这 4 段写入逻辑。
- **验证**：全量 id 交叉核查后"引用不存在的 id"归零；健康卡的电池/温度（另一套 id）显示正常。

### 1.6 首屏「0 个采样点」

- **现象**：刚打开大屏时，波形图旁显示「0 个采样点」，最长 1 分钟后才变成 30。
- **根因**：写标签的代码在图表数据填充之前执行。
- **修复**：在图表 `update()` 之后同步刷新该标签。

### 1.7 极速模式存在重复请求

- **现象**：不易察觉的额度浪费。
- **根因**：「2 秒轮询」与「每 10 秒槽位补抓 2 次」两套机制重叠，同一时刻重复取数。
- **修复**（按决策）：取消 2 秒轮询，极速模式改为**仅由 10 秒槽位双采驱动**；按钮改名「⚡ 10秒极速」，避免文案与实际行为不符。
- **验证**：模式切换正常，数据延迟保持 0~5 秒。

### 1.8 删除用户缺少二次确认

- **现象**：用户列表点「删除」立即生效，无确认步骤。
- **根因**：删除表单直接 POST。
- **修复**：服务端渲染与客户端重渲染两处都加 `onsubmit="return confirm(...)"`；确认文案中的用户名经安全处理（见 1.9）。

### 1.9 用户名字段未转义（存储型 XSS 风险）

- **现象**：名字里含 `<`、引号等字符时可能破坏页面结构；恶意构造可注入脚本。
- **根因**：服务端行渲染、客户端表格/排行榜/下拉框、以及内联进 `<script>` 的用户 JSON 均未做转义。
- **修复**：
  - 服务端新增 `escHtml` / `escJsAttr`，用于用户名、出口 IP、token、同步次数等外来文本；
  - 页面端新增 `escPage` / `safeName`，覆盖表格、排行榜、域名下拉、确认框文案；
  - 内联 JSON 额外转义 `< > &` 与行分隔符（U+2028/U+2029），防止提前闭合脚本块。
- **实现注意**：大屏页面整体位于**模板字符串**内，反斜杠会被提前处理，因此确认框文案改用"无引号/无反斜杠"的安全实现，并在本地渲染出页面后做语法与 id 校验。

## 2. 后端（Worker）问题

### 2.1 对象字面量中重复键 `totalSample`

- **现象**：功能正常（两处取值恰好相同），但属于埋雷。
- **根因**：同一对象里 `totalSample` 写了两次，后者覆盖前者；一旦只改其中一处就会静默失效。
- **修复**：删除多余的一行（保留由本轮计算赋值的那一处）。

### 2.2 每次打开大屏都会自动下发全速扫描

- **现象**：打开/刷新页面即触发手机 55 节点全速巡检（约 5.5 分钟），并产生 1 次 KV 写 + 1 次 KV 删。
- **根因**：页面加载 1.5 秒后自动 POST 扫描指令；与"仅手动触发"的注释相矛盾。
- **修复**（按决策）：**删除自动触发**，只保留「⚡ 手动刷新」按钮。
- **验证**：新开页面 24 秒后手机仍为常规节奏（nodeFast=0），KV 写入计数不变。

### 2.3 云端 KV 遗留键清理

- **现象**：KV 中存在早期版本留下的 5 个键（`stats:latest` 与若干 `user:*`），现代码已不读写。
- **根因**：历史架构遗留（实时数据已迁移到内存 + Cache API；用户库合并为单键）。
- **修复**：先导出这些键的值到本地备份，再逐个删除；清理后 KV 只剩 3 个 `noc:*` 键。
- **验证**：删除后全套接口冒烟通过（数据接口 200、无密码 401、订阅 200）。

### 2.4 规范问题（按决策不改，仅记录）

- `/api/report_traffic` 非 POST 返回 404（更规范应为 405）；
- `/admin` 未认证返回 200 + 登录页（更严格应为 401，但浏览器直接访问时体验更差）。

> 决策：保持现状，不影响功能。

## 3. 手机侧采集脚本整改

### 3.1 脚本副本治理（消除"改错文件"风险）

- **问题**：本地同时存在两份用途相同但内容不同的上报脚本；旧交接文档的说明已过期，容易改到不生效的那一份。
- **诊断方法**：通过 ADB 对手机与本地逐文件做 MD5 比对。
- **结论**：手机实际运行的是 `report_traffic.sh`（与本地逐字节一致）；另一份为过期副本。
- **处理**：过期副本重命名归档；同时发现手机上 `run_daemon.sh` 为旧版（缺少"启动后真实存活检查"等修复），已同步为新版并在手机保留原文件备份。
  → 该问题在第二轮的 **B19** 里有完整说明（根因、修法、验证方式）。

### 3.2 探测并发硬性 ≤ 2

- **问题**：手机上同时运行多个探测脚本（区域扫描、节点探测、边缘探针，手动刷新时再加全速扫描），峰值并发不受控；另发现 2 个重复的探针实例。
- **修复**：
  - 新增 `probe_gate.sh`：基于 `mkdir` 原子操作的**两个名额通行证**，探测前占位、测完释放，持有者被杀后名额可被自动回收；
  - 区域扫描、节点探测、边缘探针、全速扫描四个脚本全部接入；
  - 清理重复实例，重启后每个脚本仅保留 1 个实例。
- **验证**：
  - 4 个并发争抢 2 个名额的算法自测：峰值 = 2；
  - 100 秒采样（期间触发一次手动刷新制造最坏情况）：名额占用峰值 = 2、超限 0 次；
  - 探测数据仍正常推进（节点索引、六区时间戳按槽位更新）；
  - **隧道进程（xray / cloudflared / 看门狗）PID 全程未变，用户无断线**。

## 8. 边缘 Worker（后端）

### A1 `[致命]` 模块顶层读取 `env` —— Worker 加载即崩

- **现象**：部署后**所有**接口 500；Cloudflare 部署接口直接报
  `code 10021 Uncaught ReferenceError: env is not defined`，**拒绝部署**。
- **根因**：`env` **只作为 `fetch(request, env)` 的形参存在**，模块顶层没有这个对象。
  把运行期配置写成顶层常量并直接读 `env`，模块加载阶段就抛错。
- **影响**：不是某个功能坏，是**整个 Worker 不可用**。
- **修复**：引入运行期配置容器与读取器，消除顶层的裸 `env` 引用：
  ```js
  let _CFG = (typeof globalThis !== 'undefined' && globalThis.__WORKER_ENV) || {};
  function __setCfg(e) { _CFG = e || {}; }      // 便于测试注入
  function _cfg(key, fallback) { /* 取值，空值回退 */ }
  const ADMIN_PASSWORD = _cfg('ADMIN_PASSWORD', 'CHANGE_ME');
  ```
- **位置**：`edge/worker_deploy.js` L68-95
- **验证**：以 ES 模块方式 `import()` Worker，确认无异常；
  再用 `__setCfg()` 注入假配置，确认顶层常量取到的是注入值。

### A2 `[致命]` 顶层常量在 `_CFG` 初始化之前调用 `_cfg` —— 时序错误（TDZ）

- **现象**：`Cannot access '_CFG' before initialization`，Worker 加载即崩。
- **根因**：`_cfg()` 内部读模块级变量 `_CFG`，而 `_CFG` 在文件**靠后处**才初始化。
  位于文件**顶部**的常量若在定义时立即调用 `_cfg()`，就落在 `_CFG` 的**暂时性死区**里。
- **影响**：同 A1，整个 Worker 不可用。**这是修 A1 时新引入的问题** ——
  说明"修一个致命项"本身也可能引入另一个致命项，必须重新验证。
- **修复**：凡是定义在 `_CFG` 之前、又需要读配置的值，改成**惰性函数**：
  ```js
  function _dayTz() { return _cfg('DAY_TZ', 'UTC') || 'UTC'; }
  // 使用点：timeZone: _dayTz()
  ```
- **位置**：`edge/worker_deploy.js` L19（定义）、L1134/L1135/L1158 等（使用点）
- **验证**：模块载入必须通过；另加一条静态检查"使用点是否全部改成调用"，防止漏改复发。

### A3 运行期配置被写成**字符串字面量**，运行时不会被求值

- **现象**：
  - 隧道探活打到字面量域名上，永远失败 → 管理面误判"链路断了"；
  - 用户标识返回一串占位文本，**不是合法 UUID**，Xray 拒绝启动。
- **根因**：脱敏/模板化过程中真实值被换成 `${KEY}` 形式并被**引号包住**
  （如 `"${TUNNEL_HOST}"`、`'${VLESS_UUID}'`）。在 JS 里这只是**普通字符串**，不做插值；
  若外层是单引号，连模板插值都不成立。
- **修复**：分三类处理，**不能一刀切**：
  1. 服务端普通表达式 → 走 `_cfg('KEY', ...)`；
  2. 页面模板内、希望浏览器看到字面值的 → 保留 `${KEY}` 插值（渲染期求值）；
  3. 模板字符串**外**的 → **绝不**插入 `${...}`，否则是语法错误。
- **位置**：`edge/worker_deploy.js` L1972（探活）、L104（用户标识映射）
- **验证**：静态扫描"代码行里仍存在的 `${VAR}`"，并区分"是否在反引号模板内"。

### A4 `[新增]` `shared_legacy` 兼容位留下非法 UUID

- **现象**：配置里出现非 UUID 字符串当作用户 id，Xray 拒绝加载。
- **根因**：该条是历史共享用户的兼容位（其流量会被归属到某个现有用户）。
  脱敏把它的 UUID 换成了 `${USER_UUID}`，但**部署流程里没有这个键**，于是原样推给设备。
- **影响**：设备上 Xray 起不来（表现为"节点没反应"）。
- **修复**：给一个**格式合法且互不相同**的占位 UUID，并注明可整行删除。
- **位置**：`edge/worker_deploy.js` L142
- **验证**：断言产物里 **0 处** `${USER_UUID}` 残留；**有残留就拒绝输出**（宁可不出包）。

### B8 用户库读取缺少兜底链 —— 累计流量被抹成空

- **现象**：手机已报"每人累计流量 8.79 GB"，大屏只显示 24 MB；几分钟后甚至归零。
- **根因**：手机每 6 秒上报一次，会落到**不同 isolate**（内存互不可见）。
  某些轮次里"按需才发"的字段（每人累计流量、15 分钟历史、节点状态）缺失，
  表达式得到 `undefined`，而 `JSON.stringify` 会**整个键丢掉**，
  于是退回 Worker 侧会话累加器（数值小得多）。
- **影响**：数据看起来在动，但**不是真值**；跨机房还会看到不同数字。
- **修复**：三级兜底，顺序不能变：
  **isolate 内存 → 同机房共享 Cache 快照 → 上一份快照**；
  并对"只能增"的累计值额外取 `max(旧, 新)`，防止读取失败导致数值回退。
- **位置**：`edge/worker_deploy.js`（用户库读取与兜底链）

### E9 管理面全绿 ≠ 代理可用 —— 缺少业务链路验收

- **现象**：接口全 200、版本号一致、数据在流动，**但代理其实连不通**
  （鉴权失败、隧道到源站断了、客户端参数不对都可能是绿的）。
- **根因**：原有验收只覆盖**管理面**（接口连通、版本一致、数据新鲜度），
  没有任何一项验证"真的能从这条链路出去"。
- **影响**：把"看起来正常"当成"部署成功"，故障被掩盖。
- **修复**：验收脚本增加**真实出口核对**：
  ① 让节点自己报一次出口 IP；② 从本机经一条订阅路径发真实请求取出口 IP；③ 两者比对。
  > ⚠ 若本机与节点**在同一网络**，两个出口 IP 会相同，此时该方法**无法区分**
  > "走了代理"和"没走代理"。脚本必须明确提示这一点，**不假装通过**。
- **位置**：`deploy/step4_verify.py`（业务链路验收段）
- **验证**：见第 13 节的实测记录（含"用节点侧计数增长作为旁证"的办法）。

## 9. 管理页（前端）

### C5 `[致命]` 页面模板引用了未定义变量 —— 整页打不开

- **现象**：`/admin` 报错或白屏；服务端渲染阶段抛 `ReferenceError`。
- **根因**：页面模板里引用了若干**设备/系统变量**（设备名、芯片、运营商、系统版本）。
  这些原本写死为真实机型，脱敏后成了**未定义变量**；模板字符串在服务端求值时立即抛错。
- **影响**：整个管理页不可用（不只是某个数字不显示）。
- **修复**：在服务端作用域补**中性默认值**，并允许同名配置覆盖：
  ```js
  const DEVICE_NAME = _cfg('DEVICE_NAME', '未上报');
  ```
  ⚠ 这些常量必须定义在 `_cfg` **之后**（否则就是 A2）。
- **位置**：`edge/worker_deploy.js` L83-90
- **验证**：载入 Worker 后请求 `/admin`，断言 200 且不再含未定义标识符。

### C6 `[致命]` 页面模板**注释**里的 `${变量}` 也会被求值

- **现象**：整页渲染抛 `ReferenceError`，报错位置"看起来只是条注释"。
- **根因**：页面是**模板字符串**。反引号内的 `${...}` **无论在注释里还是代码里都会被求值**
  —— 注释不能让它免于执行。
- **影响**：同 C5，整页打不开。
- **修复**：注释里想显示 `${X}` 字样时用反斜杠转义：`\${X}`。
- **位置**：`edge/worker_deploy.js`（页面模板内的说明性注释）
- **验证**：扫描页面模板中所有未被转义的 `${...}`，逐个确认名字有定义。

### C7 浏览器侧引用服务端 `env` —— 前端必然失效

- **现象**：管理页里依赖管理口令的功能静默失效（浏览器控制台报 `env is not defined`）。
- **根因**：前端脚本里直接写了 `env.ADMIN_PASSWORD`。浏览器环境**没有** `env` 对象。
- **影响**：前端长轮询、手动刷新等需要口令的调用全部失败。
- **修复**：渲染页面时把配置**注入页面**，前端统一从注入对象读：
  ```js
  // 服务端渲染时注入
  window.__CFG = { ADMIN_PASSWORD: '${ADMIN_PASSWORD}' };
  // 前端使用
  window.__CFG.ADMIN_PASSWORD
  ```
- **位置**：`edge/worker_deploy.js` L4586（注入）、L3893 等（使用）
- **验证**：静态检查前端脚本块里**不再出现** `env.`，并确认注入点存在。

### C10 仪表盘口径与标题不符 —— 名义"带宽"实际只显示上行

- **现象**：卡片叫「实时上行带宽负荷」，但用户要看的是**整条链路占了多少带宽**；
  下行占大头时仪表盘几乎不动。
- **根因**：指标只取 `liveRate.up`，把下行排除在外。**标题与数值口径不一致**。
- **影响**：误判"带宽很空"，与真实负载不符。
- **修复**：改为**上行 + 下行合计**，标题同步改为「实时总带宽负荷 (上行+下行 · Max 150M)」：
  ```js
  const _bwTotal = Number(m.up) + _bwDown;
  ```
- **位置**：`edge/worker_deploy.js` L3397 起（面板）、L3940 附近（渲染）
- **验证**：断言新文案与三个指标格存在、旧文案已移除。

### C11 「近 15 分钟峰值」是假口径 —— 实际只统计当前浏览器会话

- **现象**：刷新页面后峰值归零；换个浏览器看又是另一个数。
- **根因**：峰值存在 `window._peakUpMbps` 里，只在**当前页面会话**内累加，
  既不是 15 分钟窗口，也不跨刷新；它还只统计**上行**，与标题本意不符。
- **影响**：这是一个"看起来有数据、其实不可信"的指标 —— **比没有更糟**。
- **修复**：把统计**下沉到节点**（手机每 30 秒一个采样点、保留 30 点 = 正好 15 分钟），
  随上报一起送回；前端只负责显示。当日峰值按日界线重置并落盘，
  刷新/换浏览器/换电脑都不丢。
- **位置**：`phone/scripts/report_traffic.sh` L481 起（统计）、
  `edge/worker_deploy.js` L3940 起（显示）
- **验证**：用**从脚本里原样抽出**的代码段跑真实 `sh`+`awk`，覆盖 6 个场景
  （空历史 / 单点 / 多点取最大 / 新值更低保持 / 新值更高抬升 / 跨日重置），全部通过。

### C12 `[新增]` 峰值改为节点统计后，推送路径拿不到数据

- **现象**：面板上总流量与两个峰值要等约 60 秒才更新一次，而其它数字 6 秒就动。
- **根因**：6 秒的推送接口（`/api/live`）返回的是**精简快照**，
  只有 `up/down/pings` 等字段，**不含** `downBytes/upBytes/bwPeak`；
  而显示函数按"完整 stats"来读，于是只在 60 秒轮询那一拍才有值。
- **影响**：面板刷新节奏不一致，观感像"卡住了"。
- **修复**：把最近一次完整 stats 缓存在客户端，两条路径都读它：
  ```js
  window.__lastFullStats = d;    // 轮询拿到完整数据时缓存
  applyBwPanel();                // 显示函数不传参，内部读缓存
  ```
- **位置**：`edge/worker_deploy.js` L4817（缓存）、L7453（推送路径调用）
- **验证**：先确认推送消息里确实没有这些字段（**不是靠猜**），
  再确认显示函数不传参时能取到缓存。

### C13 `[新增]` 页面模板转义缺失

- **现象**：整页渲染抛错，位置在一条**说明性注释**里。
- **根因**：注释里写了 `${WIFI_SSID}` 想表达"这里曾经是写死的 WiFi 名"，
  但它在模板字符串里，会被当真求值。（与 C6 同源，独立出现）
- **修复**：转义为 `\${WIFI_SSID}`。
- **验证**：同 C6。

### C14 数据"看起来新鲜"的伪装

- **现象**：没有任何真实上报时，页面显示"刚刚 / 0 秒前"。
- **根因**：冷启动快照把 `timestamp` 填成了服务端当前时间，于是"年龄"算出来永远是 0。
- **影响**：违背"测不到就显示未测到"的原则，让人误以为系统在正常工作。
- **修复**：冷启动 `timestamp = 0`，前端按"未测到"渲染；收到第一份真实上报后自动变成真实年龄。
- **位置**：`edge/worker_deploy.js`（冷启动快照构造）
- **验证**：断言冷启动分支 `timestamp` 为 0，且不存在假电量/假 WiFi 等占位数据。

## 10. 节点脚本（手机侧）

### B15 配置**文件名**不一致 —— 新设备起不来

- **现象**：部署脚本报告"配置已推送"，但设备上 Xray/隧道起不来；
  老设备则表现为"推了新配置但行为没变"（继续跑旧配置）。
- **根因**：部署脚本用「文件名去掉 `.example`」推断运行文件名，
  于是生成了 `phone_active_config.json`、`termux_config.yml` 之类，
  而启动脚本读的是 `config.json` 与 `config.yml`。**名字对不上**。
- **影响**：新设备无法启动；老设备配置更新**静默失效**（推送成功 ≠ 生效）。
- **修复**：改为**显式映射表**（源样例名 → 设备运行文件名）；
  没有映射的样例**直接中止**，避免又推错名字。
- **位置**：`deploy/step3_deploy_node.py`（配置映射段）
- **验证**：断言"部署生成的名字"与"启动脚本读取的名字"一致。

### B16 配置样例的传输协议与实际不符 —— 照着配连不上

- **现象**：按仓库里的配置样例搭好，客户端连不上或立刻断。
- **根因**：样例是早期用 **WS/gRPC** 传输时的历史快照，
  而设备与运行时生成的都是 **XHTTP**。样例与真实链路**不是一回事**。
- **影响**：新人照着配必然失败，且协议不匹配的报错很晦涩，很难定位。
- **修复**：
  1. `config.json.example` 改为**由运行时配置生成函数导出**，格式一定正确；
  2. `config.yml.example` 补齐隧道必需的 `tunnel:` 与 `credentials-file:` 两行；
  3. 删掉过期的 WS/gRPC 快照，避免继续误导。
- **位置**：`phone/config/`（`config.json.example` / `config.yml.example` / `README.md`）
- **验证**：断言样例传输协议全为 `xhttp`、路径集合与设备一致、是合法 JSON。

### B17 `[新增]` 时区写死 —— 日界线无法按部署地调整

- **现象**：非东八区部署时，"今日流量/当日峰值"的换日时刻与本地不符。
- **根因**：日界线时区在代码里写死；而且它是"地名"形态，
  与"仓库内不出现地名"的要求冲突 —— 但**直接删掉会让功能失效**。
- **影响**：统计口径与使用者日历不一致；若两边不一致，数字会对不上。
- **修复**：做成**可配置项**，并让节点取同一个值，保证两边永远一致：
  - Worker：`function _dayTz() { return _cfg('DAY_TZ', 'UTC') || 'UTC'; }`
  - 配置：`.env` 的 `DAY_TZ`
  - 下发：随节点配置一起带 `dayTz` 字段（Xray 忽略未知顶层字段，已实测）
  - 节点：从配置里取，取不到再退回设备本地时区
- **位置**：`edge/worker_deploy.js` L19 / L160、`phone/scripts/report_traffic.sh` L502
- **验证**：① 实测 Xray 接受自定义顶层字段（`-test` 通过）；
  ② 断言整仓无写死地名，同时时区仍可配置。

### B18 同步脚本失败仍推进版本号 —— 静默的数据不一致

- **现象**：同步失败后版本号却前进了，于是**不再重试**；
  云端显示"已同步"，设备实际还是旧配置。
- **根因**：脚本在 `curl` 之后**无条件**写入版本号，没有校验 HTTP 状态与内容；
  启动失败也没有回滚。
- **影响**：用户库/配置长期不同步且**没有任何报错** —— 最难发现的一类问题。
- **修复**：
  - `curl` 前先删目标文件，避免"上一轮残留被当成这一轮成功"；
  - 校验退出码 + HTTP 状态码 + 文件非空；
  - 数据陈旧 / 拉取失败 → **立即结束本轮，不写版本号**；
  - 版本号改为**确认 Xray 存活之后**才写；
  - 启动失败 → 从备份回滚配置。
- **位置**：`phone/scripts/sync_worker.sh`
- **验证**：离线模拟失败场景，断言"版本号不前进、立即结束、失败回滚"。

### B19 启动脚本无条件报"成功"

- **现象**：脚本打印"所有守护进程已启动"，但进程其实没起来。
- **根因**：启动后只 `echo` 一句话，**没有任何存活检查**。
- **影响**：自动化流程误判成功，后续步骤全部建立在错误前提上。
- **修复**：启动前检查必需文件、启动后用 `pgrep` 检查进程；
  任一缺失就打印明确原因并 `exit 1`；日志里注明"进程存在 ≠ 隧道已连通"。
- **位置**：`phone/scripts/run_daemon.sh` L25 / L43-45 / L51
- **验证**：缺文件、缺进程两种情况下断言退出码非 0。

- **修复**：注入后**重新扫描残留占位符**，只要还有就中止并**列出缺失项**。

- **验证**：断言 `chmod` 与复查逻辑存在且能中止。

## 12. 脱敏/导出流程自身引入的缺陷

这一节单独列出，因为它的特点是：**症状出现在产物里，根因在导出工具里**，
而且往往能通过语法检查。

### X29 关键词替换误伤正常单词

- **现象**：节点脚本里 `echo "MISSING: $f"` 被改成了 `echo "MISPOP2G: $f"`。
- **根因**：三字母机房码用**无边界**替换，`SIN` 命中了 `misSINg`。
  同类还有 `CAN` 会命中 `CANnot` 等。
- **影响**：**静默改坏字符串** —— 不报错，但行为变了
  （提示信息错乱，严重时改坏变量名或命令）。
- **修复**：改为按**独立单词**匹配。注意**不能用 `\b`**：
  在 Unicode 下 `\b` 遇到中文会失效，要用显式环视：
  ```python
  re.compile(r'(?<![A-Za-z])%s(?![A-Za-z])' % code)
  ```
- **验证**：改完后**重新统计替换次数**，确认没有"少替换"；
  并单独断言 `MISSING` 这类正常单词未被破坏。
  > 这一步很重要：加了边界后替换数会下降，必须确认下降是"少了误伤"，
  > 而不是"漏了真替换"。

### X30 `[新增]` 自引用占位符 —— 值变成占位符自己的名字

- **现象**：时区配置被求值成字符串 `"DAY_TZ"`；日期格式化拿到无效时区。
- **根因**：脱敏把 `'Asia/Shanghai'` 换成了 `'${DAY_TZ}'`，
  在 JS 模板字符串里 `${DAY_TZ}` 会**引用同名变量自己** —— 自引用。
- **修复**：定义处**整行重写**（用通用正则匹配整行，不依赖具体形态），
  并断言"代码行里不再有裸占位符"。
- **验证**：断言惰性函数定义存在、使用点全部改成调用、代码行残留为 0。

### X31 重复赋值 —— 前一处配置被后一处写死值覆盖

- **现象**：样例脚本里同一变量被赋值两次，后者是写死值，
  于是前面"从配置读"的改动**完全失效**。
- **根因**：改写脚本时按"第一个赋值点"截断，把后面的旧赋值段原样保留了。
- **修复**：删掉重复段，只保留读配置的赋值。
- **验证**：断言每个变量**只出现一次**赋值。

### X32 `[新增]` 遗留脚本会注入**假数据**

- **现象**：该脚本往 Worker 里写"看起来合理"的兜底数值
  （假时延、假电量、假 WiFi 名、假在线时长）。
- **根因**：早期为了让大屏"不空"刻意加了假兜底；正式代码后来已改成
  "缺就显示未测到"，但这个一次性迁移脚本仍留在仓库里，
  既跑不通（匹配的旧代码已不存在）又是个**错误示范**。
- **影响**：谁照着它做，就会把假数据引入系统。
- **修复**：从公开产物中**移除**该脚本，并注明移除原因。
- **验证**：断言该文件不在产物中。

## 13. 第二轮验收方式（可复现）

按顺序跑，每步都能独立发现问题。**不要跳步**：

| 步骤 | 命令 | 通过标准 |
|---|---|---|
| 1. 语法 | `node --check edge/worker_deploy.js`、`compile()` 全部 `.py`、`bash -n` 全部 `.sh` | 0 失败 |
| 2. **可加载** | 以 ES 模块方式 `import()` Worker | **无异常** |
| 3. 死占位符 | 扫描代码行里的 `${VAR}`，区分是否在模板内 | 0 处非预期残留 |
| 4. 部署入口 | `python deploy/step1_check.py` | 能启动并给出清晰阻塞项列表 |
| 5. 线上验收 | `python deploy/step4_verify.py` | 接口/版本/数据流/占位符/**业务链路** 全过 |
| 6. 脱敏核查 | `python tools/check_secrets.py` | 0 处残留 |
| 7. 节点逻辑 | 从脚本**原样抽出**代码段跑真实 `sh`+`awk` | 场景断言全过 |
| 8. 真实出口 | 经代理访问一个 HTTPS 目标 | 出口 IP 与节点一致（或同网段） |

> **第 2 步不可省。** 本轮 6 个致命项里有 3 个能通过第 1 步，
> 只在第 2 步或第 5 步才会暴露。

**真实出口验收的实测记录**（用于说明"同网络下怎么判"）：

| 步骤 | 观察 |
|---|---|
| 节点直连出口 | 拿到节点所在网络的出口 IP 与国家/地区码 |
| 经代理访问 HTTPS | TLS 校验通过，返回同一国家/地区码 |
| 旁证 | 节点侧入站计数**增长** → 证明流量确实穿过了节点 |
| 对照组 | 本机直连时节点侧计数**不增长** → 排除"计数因其它原因增长" |

> 若本机与节点在同一网络，出口 IP 相同，**该方法无法区分**是否走了代理 ——
> 必须补上"节点侧计数"这类旁证，不能只比 IP。

## 15. 哪些写法还会再踩（第二轮总结）

1. **顶层读 `env`** → 必崩。运行期配置一律走读取器。
2. **在 `_CFG` 之前调用 `_cfg()`** → TDZ。用惰性函数。
3. **模板字符串的注释里写 `${...}`** → 照样求值。要转义。
4. **用"去掉后缀"推断运行文件名** → 迟早对不上。用显式映射表。
5. **失败后仍推进游标/版本号** → 静默不一致。失败必须阻断。
6. **短关键词无边界替换** → 误伤正常单词。用环视断言（不是 `\b`）。
7. **`node --check` 通过就以为能跑** → 加载期与运行期错误它抓不到。
8. **只验管理面** → 代理不通也能全绿。必须验业务链路。
9. **修完一个致命项就以为完事** → A2 正是修 A1 时引入的。改完必须重新走一遍验收。

徽标有 5 种状态，颜色区分：

| 状态 | 文案 | 颜色 |
|---|---|---|
| 初始 | 手机主库：检测中… | 灰 |
| 无数据 | 手机主库：等待手机上报… | 灰 |
| 已同步 | 手机主库：已同步 ✓ `<版本>`（`N` 秒前）· 已确认 `时间` | 绿 |
| 待同步 | 手机主库：待同步（上报于 `N` 秒前） | 黄 |
| 指令进行中 | 手机主库：已下发指令 · 等待手机取走（`N` 秒前）… / 正在重新拉取并确认…（`N` 秒） | 黄 |
| 异常 | 手机主库：指令下发失败 / 等待确认超时，可再点一次刷新 | 红 |

## 三、完整链路

```
你在后台点【⟳ 刷新】
   │  POST /api/phone_sync
   ▼
Worker 写 KV 键 noc:sync:req { id, at }        ← 全项目唯一"按点击写 KV"的地方
   │  （手机每约 6 秒上报一次，上报响应里带回 syncRequest）
   ▼
手机收到新指令
   ├─ 写入 /data/local/tmp/last_sync_req.txt
   └─ touch /data/local/tmp/force_sync
   │  ★ 第 7 节紧接着读这个标记 → 同一次运行内立即强制重新拉取
   ▼
手机重新拉取 users.json + config.json
   ├─ cmp 比对配置：内容一致 → 不重启 xray（零中断）
   └─ 内容有变 → 才 pkill + 重启
   │  下一轮上报带上 syncAck = 指令 id
   ▼
Worker 收到 ack → 删除 KV 键 → 记录 ackedAt
   │
   ▼
后台徽标变为「已同步 ✓ … · 已确认 11:52:37」
```

**实测往返耗时：10.9 ~ 13.5 秒。**

| **10-03（现在）** | **237 / 100,000 (0.24%)** | **2 / 1,000 (0.2%)** | **1 / 1,000** |

本功能的 KV 开销：

- **写 / 删**：每次点击各 1 次 → 一天点几次就是几次，可忽略
- **读**：手机每次上报读一次指令键（**故意不加 cacheTtl**，保证点击后立即生效）
  → 约 14,400 次/天，占免费读额度 **14.4%**，合规

> 想进一步省读：把 `worker_deploy.js` 里的 `SYNC_REQ_CACHE_TTL` 从 `0` 改成 `30`，
> 读量降到约 2,880 次/天（2.9%），代价是点击后最多 30 秒才被手机取到。

## 八、注意事项

1. **点击刷新会强制手机重新拉取配置**。若配置内容与手机现有的一致（绝大多数情况下如此），
   已做优化**不会重启 xray**，朋友无感；只有当成员真的变了才会重启（约 1 秒）。
2. **手机必须在线**：手机离线时点刷新会等待 30 秒后提示「等待确认超时」。
3. **自动同步仍然生效**：增/禁/删后手机仍在约 6 秒内自动生效，刷新按钮只是让你能立刻确认或强制重取。
4. **CF API Token 仍需轮换**（旧 Token 已泄露），已收敛到 `.cf_token` 单点。

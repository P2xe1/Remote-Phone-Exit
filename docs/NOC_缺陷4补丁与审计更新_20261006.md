## 1. P1 · 峰值缓存复用分支未生效

### 1.1 位置

节点脚本 `report_traffic.sh`（带宽峰值段落 + 非重算周期复用分支）。

### 1.2 现象与证据

上一轮修复部署后，对设备上"待上报载荷"文件连续采样 8 次：

| 采样 | 载荷是否含峰值字段 | 值 |
| --- | --- | --- |
| 8 次中的 1 次 | 有（恰为 30 秒重算轮） | 15 分钟峰值正常 |
| 8 次中的其余 7 次 | **无** | — |

与修复前"约 80% 轮次缺字段"的模式**完全一致** —— 说明补字段的复用分支从未执行。

### 1.3 根因

"峰值缓存文件路径"这一变量原先只定义在**每 30 秒才进入一次的重算块内部**；
而"非重算周期从缓存补齐字段"的分支写在重算块**外面**。
每约 6 秒执行一次、执行完即退出的普通轮次中，该变量为空，
判定语句退化为"对一个空路径判断文件是否存在"（恒为假），复用分支因此从未执行。

### 1.4 为什么上一轮单测没有发现

上一轮的设备侧单测在调用被测代码块**之前**先手工定义了该路径变量，
恰好绕开了真实调用环境中的变量作用域问题。属于**测试方法缺陷**，记录在案；
本次改用"真机真实调度链路 + 连采 8 次"的验收方式，不再依赖隔离单测。

### 1.5 修法（2 处，均只动这一段）

1. 把峰值缓存文件路径**移到脚本顶部全局常量区**（与其它路径常量放在一起）；
2. 30 秒重算块内的写盘动作改为**每次重算都写**。
   原写法"只在日峰值变大时才写"会让文件长期停留在两字段的旧格式，
   复用分支取不到 15 分钟值，只能按 0 上报 —— 等于没修。
   该文件是设备本地小文件（几十字节），30 秒写一次的代价可忽略。

### 1.6 部署方式与安全措施

| 项 | 做法 |
| --- | --- |
| 替换方式 | 先推送至暂存文件 → 校验哈希一致 → **原子改名**覆盖，杜绝"半截文件"被读取 |
| 服务中断 | **零**：不重启任何进程（核心进程运行时长连续未断） |
| 切换保护 | 替换前用最近一次**真实**峰值预写缓存文件，避免切换瞬间监控台显示 0 |
| 回滚 | 部署前版本已完整备份，推回即还原 |

### 1.7 验证（真机 + 线上）

| 验证项 | 结果 |
| --- | --- |
| 连采 8 次待上报载荷 | **8/8 全部带峰值字段** |
| 缓存文件修改时间 | 每约 30 秒推进一次（重算在持续刷新） |
| 线上接口连续 3 次读取 | 峰值稳定、数据年龄 1~5 秒 |
| 核心进程 | 进程号与运行时长连续，未重启 |

### 1.8 额度影响

只写设备本地小文件（几十字节 / 30 秒），**不涉及云端存储，零写入**。

## 2. P2 · 审计脚本过期断言清理

### 2.1 位置

审计脚本 `full_audit.py` 第 3 步（页面元素检查）与第 4 步（浏览器实测读数）。

### 2.2 原状

1. 断言页面必须存在 5 个"区域网关"元素 —— 该 UI 区块早已按需求删除，
   线上页面实测 5 个元素命中均为 **0**，断言**永远失败**；
2. 断言页面必须包含旧表头文字"连接状态 (5秒检测)" —— 文案已随改版更名，
   旧字符串命中为 **0**，断言同样**永远失败**。

### 2.3 修法

1. 改为检查**现在真实存在**的"带宽峰值面板"两个元素；
2. 改为检查"连接状态板块"两个元素 id；
3. 第 4 步浏览器实测的读数同步改为读取现有元素（不再读取已删除的旧元素）。

### 2.4 验证

完整运行审计脚本，**四步全绿**：

| 步骤 | 结果 |
| --- | --- |
| 1/4 数据接口 | 通过（遥测 / 网关延迟 / 8 位用户 / 累计流量） |
| 2/4 订阅接口 | 通过（Clash 59 节点 + 核心分组；V2Ray 解码 56 条链接） |
| 3/4 页面元素 | **15 项检查全部 PASS**（含两条本次替换后的新检查） |
| 4/4 浏览器实测 | 通过（60s/2s 模式切换、峰值 18.88 / 26.56 Mbps、E2E 104 ms） |

输出结论：`ALL SYSTEMS VERIFIED & 100% OPERATIONAL`。

> 说明：审计脚本是仓库内的自检工具，不参与线上服务，不影响用户。

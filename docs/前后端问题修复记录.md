# 前后端问题修复记录（逐项原因 + 修复）

本文记录本项目在**一次完整审查**中发现并修掉的全部缺陷，按**所在层**分类。
每一项都写清四件事：**症状 → 根因 → 影响面 → 修法**，并给出修复后的代码位置。

> **怎么读这份文档**
> - 如果你只是使用者：看每项的「症状」一栏即可，能帮你判断"我遇到的是不是这个问题"。
> - 如果你要改代码：先看「根因」和「修法」——里面很多坑是**同类写法还会再踩**的。
> - 行号对应本仓库当前版本；行号会随改动漂移，定位时请以**特征字符串**为准。
>
> **编号说明**：`A*` = 会导致 Worker 加载失败/拒绝部署的致命项；
> `B*` = 节点（手机）侧；`C*` = 管理页（前端）；`D*` = 部署工具；
> `E*` = 数据口径与验收。编号前的 `[新增]` 表示这一项**不在原始审查清单里**，
> 是修复过程中另外发现并确认的。

## 1. 边缘 Worker（后端）

### A1 `[致命]` 模块顶层读取 `env` —— Worker 加载即崩

- **症状**：部署后**所有**接口返回 500；Cloudflare 部署接口直接报
  `code 10021 Uncaught ReferenceError: env is not defined`，拒绝部署。
- **根因**：`env` **只作为 `fetch(request, env)` 的形参存在**，模块顶层没有这个对象。
  把运行期配置写成顶层常量并直接读 `env`，模块加载阶段就会抛错。
- **影响面**：整个 Worker 不可用（不是某个功能坏，是全部坏）。
- **修法**：引入一个运行期配置容器与读取器，并把模块顶层对 `env` 的引用全部消除：
  ```js
  let _CFG = (typeof globalThis !== 'undefined' && globalThis.__WORKER_ENV) || {};
  function __setCfg(e) { _CFG = e || {}; }          // 便于测试注入
  function _cfg(key, fallback) { /* 取值，空值回退 */ }
  const ADMIN_PASSWORD = _cfg('ADMIN_PASSWORD', 'CHANGE_ME');
  ```
- **位置**：`edge/worker_deploy.js` L68-95
- **验证**：以 ES 模块方式载入 Worker（`import()`），确认无异常；
  再用 `__setCfg()` 注入假配置，确认顶层常量取到的是注入值。

> ⚠ **这个坑的变体**：把顶层常量改成 `_cfg(...)` 之后，**又会踩第二个坑**（见 A2）。

### A2 `[致命]` 顶层常量在 `_CFG` 初始化之前调用 `_cfg` —— 时序错误（TDZ）

- **症状**：`Cannot access '_CFG' before initialization`，Worker 加载即崩。
- **根因**：`_cfg()` 内部读的是模块级变量 `_CFG`，而 `_CFG` 在文件**靠后处**才初始化。
  位于文件**顶部**的常量如果在定义时立即调用 `_cfg()`，就落在 `_CFG` 的
  **暂时性死区（TDZ）**里。
- **影响面**：同 A1，整个 Worker 不可用。这是修 A1 时**新引入**的问题。
- **修法**：凡是定义在 `_CFG` 之前的、需要读配置的值，改成**惰性函数**——
  调用时才解析，那时 `_CFG` 早已就绪：
  ```js
  function _dayTz() { return _cfg('DAY_TZ', 'UTC') || 'UTC'; }
  // 使用点：timeZone: _dayTz()
  ```
- **位置**：`edge/worker_deploy.js` L19（定义）、L1134/L1135/L1158 等（使用点）
- **验证**：模块载入测试必须**通过**；另外要有一条"使用点已全部改成调用"的静态检查，
  防止漏改导致再次踩坑。

### A3 运行期配置被写成**字符串字面量**，运行时不会被求值

- **症状**：
  - 隧道探活打到字面量域名上，永远失败 → 管理面误判"链路断了"。
  - 用户标识返回一串占位文本，**不是合法 UUID**，Xray 直接拒绝启动。
- **根因**：脱敏/模板化过程中，真实值被替换成了 `${KEY}` 形式并被**引号包住**
  （如 `"${TUNNEL_HOST}"`、`'${VLESS_UUID}'`）。在 JS 里这只是**普通字符串**，
  不做插值；若外层是单引号则连模板插值都不成立。
- **影响面**：探活误判、串流鉴权失败（用户连不上）。
- **修法**：分三类处理，**不能一刀切**：
  1. 服务端普通表达式 → 走 `_cfg('KEY', ...)`；
  2. 页面模板内、希望浏览器看到字面值的 → 保留 `${KEY}` 插值（渲染期求值）；
  3. 模板字符串外的 → **绝不**插入 `${...}`，否则是语法错误。
- **位置**：`edge/worker_deploy.js` L1972（探活）、L104（用户标识映射）
- **验证**：静态扫描"代码行里仍存在的 `${VAR}`"，并区分"是否在反引号模板内"。

### A4 `[新增]` `shared_legacy` 兼容位留下非法 UUID

- **症状**：配置里出现一个非 UUID 的字符串当作用户 id，Xray 拒绝加载该配置。
- **根因**：该条是历史共享用户的兼容位（其流量会被归属到某个现有用户）。
  脱敏把它的 UUID 换成了 `${USER_UUID}`，但**部署流程里没有这个键**，
  于是原样推给设备。
- **影响面**：设备上 Xray 起不来（表现为"节点没反应"）。
- **修法**：给一个**格式合法且互不相同**的占位 UUID，并在旁边注明可整行删除。
- **位置**：`edge/worker_deploy.js` L142
- **验证**：断言整份产物里 **0 处** `${USER_UUID}` 残留（有残留就拒绝输出）。

### C5 `[致命]` 管理页模板引用了未定义变量 —— 整页打不开

- **症状**：`/admin` 打开报错或白屏；服务端渲染阶段抛 `ReferenceError`。
- **根因**：页面模板（反引号）里引用了若干**设备/系统变量**
  （设备名、芯片、运营商、系统版本等）。这些原本写死为真实机型，
  脱敏后成了**未定义变量**；模板字符串在服务端求值时立即抛错。
- **影响面**：整个管理页不可用（不只是某个数字不显示）。
- **修法**：在服务端作用域补上**中性默认值**，并允许用同名配置覆盖：
  ```js
  const DEVICE_NAME = _cfg('DEVICE_NAME', '未上报');
  ```
  注意 ⚠ 这些常量必须定义在 `_cfg` **之后**。
- **位置**：`edge/worker_deploy.js` L83-90
- **验证**：载入 Worker 后请求 `/admin`，断言返回 200 且页面里不再含未定义标识符。

### C6 `[致命]` 页面模板**注释**里的 `${变量}` 也会被求值

- **症状**：整页渲染抛 `ReferenceError`，而报错指向的位置"看起来只是条注释"。
- **根因**：页面是**模板字符串**。反引号内的 `${...}` **无论在注释里还是代码里
  都会被求值** —— 注释不能让它免于执行。
- **影响面**：同 C5，整页打不开。
- **修法**：注释里想显示 `${X}` 字样时，用反斜杠转义：`\${X}`。
- **位置**：`edge/worker_deploy.js`（页面模板内的说明性注释）
- **验证**：扫描页面模板中所有未被转义的 `${...}`，逐个确认名字有定义。

### C7 浏览器侧引用服务端 `env` —— 前端必然失效

- **症状**：管理页里依赖管理口令的功能静默失效（浏览器控制台报 `env is not defined`）。
- **根因**：前端脚本里直接写了 `env.ADMIN_PASSWORD`。
  浏览器环境**没有** `env` 对象（那是 Worker 运行时的东西）。
- **影响面**：前端长轮询、手动刷新等需要口令的调用全部失败。
- **修法**：渲染页面时把需要的配置**注入到页面**，前端统一从注入对象读：
  ```js
  // 服务端：渲染时注入
  window.__CFG = { ADMIN_PASSWORD: '${ADMIN_PASSWORD}' };
  // 前端：window.__CFG.ADMIN_PASSWORD
  ```
- **位置**：`edge/worker_deploy.js` L4586（注入）、L3893 等（使用）
- **验证**：静态检查前端脚本块里**不再出现** `env.`；并确认注入点存在。

### B8 用户库读取缺少兜底链 —— 累计流量被抹成空

- **症状**：手机已报"每人累计流量 8.79 GB"，大屏却只显示 24 MB；几分钟后甚至归零。
- **根因**：手机每 6 秒上报一次，会落到**不同 isolate**（内存互不可见）。
  某些轮次里"按需才发"的字段（每人累计流量、15 分钟历史、节点状态）缺失，
  表达式得到 `undefined`，而 `JSON.stringify` 会**整个键丢掉**，
  于是退回 Worker 侧会话累加器（数值小得多）。
- **影响面**：数据看起来在动，但**不是真值**；跨机房还会看到不同数字。
- **修法**：三级兜底，且顺序不能变：
  **isolate 内存 → 同机房共享 Cache 快照 → 上一份快照**；
  并对"只能增"的累计值额外取 `max(旧, 新)`，防止读取失败导致数值回退。
- **位置**：`edge/worker_deploy.js`（用户库读取与兜底链）
- **验证**：模拟"某一轮不带该字段"的上报，断言下发值**不被抹成空**。

### E9 管理面全绿 ≠ 代理可用 —— 缺少业务链路验收

- **症状**：接口全 200、版本号一致、数据在流动，**但代理其实连不通**
  （鉴权失败、隧道到源站断了、客户端参数不对都可能是绿的）。
- **根因**：原有验收只覆盖**管理面**（接口连通性、版本一致、数据新鲜度），
  没有任何一项验证"真的能从这条链路出去"。
- **影响面**：把"看起来正常"当成"部署成功"，故障被掩盖。
- **修法**：在验收脚本里增加**真实出口核对**：
  1. 让节点自己报一次出口 IP；
  2. 从本机经一条订阅路径发一次真实请求，取出口 IP；
  3. 两者比对。
  > ⚠ 若本机与节点**在同一网络**，两个出口 IP 会相同，此时该方法**无法区分**
  > "走了代理"和"没走代理"。脚本会明确提示这一点，不假装通过。
- **位置**：`deploy/step4_verify.py`（业务链路验收段）
- **验证**：实测经代理访问 HTTPS 成功，且节点侧入站计数增长（见 §6）。

## 2. 管理页（前端）

### C10 仪表盘口径与标题不符 —— 名义"带宽"实际只显示上行

- **症状**：卡片叫「实时上行带宽负荷」，但用户要看的是**整条链路占了多少带宽**；
  下行占大头的场景下，仪表盘几乎不动。
- **根因**：指标只取 `liveRate.up`，把下行排除在外。标题与数值口径不一致。
- **影响面**：误判"带宽很空"，与真实负载不符。
- **修法**：改为**上行 + 下行合计**，标题同步改为「实时总带宽负荷 (上行+下行 · Max 150M)」：
  ```js
  const _bwTotal = Number(m.up) + _bwDown;
  ```
- **位置**：`edge/worker_deploy.js` L3397 起（面板）、L3940 附近（渲染逻辑）
- **验证**：断言页面标题与三个指标格的新文案存在、旧文案已移除。

### C11 「近 15 分钟峰值」是假的口径 —— 实际只统计当前浏览器会话

- **症状**：刷新页面后峰值归零；换个浏览器看又是另一个数。
- **根因**：峰值存在 `window._peakUpMbps` 里，只在**当前页面会话**内累加，
  既不是 15 分钟窗口，也不跨刷新。它还只统计**上行**，与卡片标题的本意不符。
- **影响面**：这是一个"看起来有数据、其实不可信"的指标 —— 比没有更糟。
- **修法**：把统计**下沉到节点**（手机每 30 秒一个采样点、保留 30 点 = 正好 15 分钟），
  随上报一起送回；前端只负责显示。
- **位置**：`phone/scripts/report_traffic.sh` L481 起（统计）、
  `edge/worker_deploy.js` L3940 起（显示）
- **验证**：用**从脚本里原样抽出**的代码段跑真实 `sh`+`awk`，覆盖 6 个场景
  （空历史 / 单点 / 多点取最大 / 新值更低保持 / 新值更高抬升 / 跨日重置）。

### C12 `[新增]` 峰值改成节点统计后，推送路径拿不到数据

- **症状**：面板上的总流量与两个峰值要等约 60 秒才更新一次，而其它数字 6 秒就动。
- **根因**：6 秒的推送接口（`/api/live`）返回的是**精简快照**，
  只有 `up/down/pings` 等字段，**不含** `downBytes/upBytes/bwPeak`；
  而显示函数却按"完整 stats"来读，于是只在 60 秒轮询那一拍才有值。
- **影响面**：面板刷新节奏不一致，观感像"卡住了"。
- **修法**：把最近一次完整 stats 缓存在客户端，两条路径都读它：
  ```js
  window.__lastFullStats = d;      // 轮询拿到完整数据时缓存
  applyBwPanel();                  // 显示函数不传参，内部读缓存
  ```
- **位置**：`edge/worker_deploy.js` L4817（缓存）、L7453（推送路径调用）
- **验证**：确认推送消息里确实没有这些字段（不是靠猜），
  再确认显示函数在不传参时能取到缓存。

### C13 `[新增]` 页面模板转义缺失（与 C6 同源，独立出现）

- **症状**：整页渲染抛错，位置在一条**说明性注释**里。
- **根因**：注释里写了 `${WIFI_SSID}` 想表达"这里曾经是写死的 WiFi 名"，
  但它在模板字符串里，会被当真求值。
- **修法**：转义为 `\${WIFI_SSID}`。
- **位置**：`edge/worker_deploy.js` 页面模板内
- **验证**：同 C6。

### C14 数据"看起来新鲜"的伪装

- **症状**：没有任何真实上报时，页面显示"刚刚 / 0 秒前"。
- **根因**：冷启动快照把 `timestamp` 填成了服务端当前时间，
  于是"年龄"算出来永远是 0。
- **影响面**：违背"测不到就显示未测到"的原则 —— 让人误以为系统在正常工作。
- **修法**：冷启动 `timestamp = 0`，前端按"未测到"渲染；
  收到第一份真实上报后自动变成真实年龄。
- **位置**：`edge/worker_deploy.js`（冷启动快照构造）
- **验证**：断言冷启动分支里 `timestamp` 为 0，且不存在假电量/假 WiFi 等占位数据。

## 3. 节点脚本（手机侧）

### B15 配置**文件名**不一致 —— 新设备起不来

- **症状**：部署脚本报告"配置已推送"，但设备上 Xray/隧道起不来；
  老设备则表现为"推了新配置但行为没变"（继续跑旧配置）。
- **根因**：部署脚本用 `文件名去掉 .example` 来推断运行文件名，
  于是生成了 `phone_active_config.json`、`termux_config.yml` 之类，
  而启动脚本读的是 `config.json` 与 `config.yml`。**名字对不上**。
- **影响面**：新设备无法启动；老设备配置更新静默失效（推送成功 ≠ 生效）。
- **修法**：改为**显式映射表**，源样例名 → 设备运行文件名；
  没有映射的样例**直接中止**，避免又推错名字。
- **位置**：`deploy/step3_deploy_node.py`（配置映射段）
- **验证**：断言"部署生成的名字"与"启动脚本读取的名字"一致。

### B16 配置样例的传输协议与实际不符 —— 照着配连不上

- **症状**：按仓库里的配置样例搭好，客户端连不上或立刻断。
- **根因**：样例是早期用 **WS/gRPC** 传输时的历史快照，
  而设备与运行时生成的都是 **XHTTP**。样例与真实链路**不是一回事**。
- **影响面**：新人照着样例配，必然失败，且很难看出原因（协议不匹配的报错很晦涩）。
- **修法**：
  1. `config.json.example` 改为**由运行时的配置生成函数导出**，格式一定正确；
  2. `config.yml.example` 补齐隧道必需的 `tunnel:` 与 `credentials-file:` 两行；
  3. 删掉过期的 WS/gRPC 快照，避免继续误导。
- **位置**：`phone/config/`（`config.json.example` / `config.yml.example` / `README.md`）
- **验证**：断言样例里传输协议全为 `xhttp`、路径集合与设备一致、是合法 JSON。

### B17 `[新增]` 时区写死 —— 日界线无法按部署地调整

- **症状**：非东八区部署时，"今日流量/当日峰值"的换日时刻与本地不符。
- **根因**：日界线时区在代码里写死；而且它是"地名"形态，
  与"仓库内不出现地名"的要求冲突 —— 但**直接删掉会让功能失效**。
- **影响面**：统计口径与使用者的日历不一致；若两边不一致，数字会对不上。
- **修法**：做成**可配置项**，并让节点取同一个值，保证两边永远一致：
  - Worker：`function _dayTz() { return _cfg('DAY_TZ', 'UTC') || 'UTC'; }`
  - 配置：`.env` 的 `DAY_TZ`
  - 下发：随节点配置一起带 `dayTz` 字段（Xray 会忽略未知顶层字段，已实测）
  - 节点：从配置里取，取不到再退回设备本地时区
- **位置**：`edge/worker_deploy.js` L19 / L160、
  `phone/scripts/report_traffic.sh` L502
- **验证**：
  1. 实测 Xray 接受自定义顶层字段（`-test` 通过）；
  2. 断言整仓无写死地名，同时时区仍可配置。

### B18 同步脚本失败仍推进版本号 —— 静默的数据不一致

- **症状**：同步失败后版本号却前进了，于是**不再重试**；
  云端显示"已同步"，设备实际还是旧配置。
- **根因**：脚本在 `curl` 之后**无条件**写入版本号，没有校验 HTTP 状态与内容；
  启动失败也没有回滚。
- **影响面**：用户库/配置长期不同步，且没有任何报错 —— 最难发现的一类问题。
- **修法**：
  - `curl` 前先删目标文件，避免"上一轮残留被当成这一轮成功"；
  - 校验退出码 + HTTP 状态码 + 文件非空；
  - 数据陈旧 / 拉取失败 → **立即结束本轮，不写版本号**；
  - 版本号改为**确认 Xray 存活之后**才写；
  - 启动失败 → 从备份回滚配置。
- **位置**：`phone/scripts/sync_worker.sh`
- **验证**：离线模拟失败场景，断言"版本号不前进、立即结束、失败回滚"。

### B19 启动脚本无条件报"成功"

- **症状**：脚本打印"所有守护进程已启动"，但进程其实没起来。
- **根因**：启动后只 `echo` 一句话，**没有任何存活检查**。
- **影响面**：自动化流程误判成功，后续步骤全部建立在错误前提上。
- **修法**：启动前检查必需文件、启动后用 `pgrep` 检查进程；
  任一缺失就打印明确原因并 `exit 1`；日志里注明"进程存在 ≠ 隧道已连通"。
- **位置**：`phone/scripts/run_daemon.sh` L25 / L43-45 / L51
- **验证**：缺文件、缺进程两种情况下断言退出码非 0。

## 4. 部署工具

### D20 `[致命]` 验收脚本语法错误 —— 无法启动

- **症状**：`python deploy/step4_verify.py` 直接 `SyntaxError`。
- **根因**：一处多余的右括号。
- **影响面**：验收步骤整条不可用 —— 而这正是"发现问题"的那一步。
- **修法**：删掉多余括号。
- **位置**：`deploy/step4_verify.py`
- **验证**：`compile()` 全部 Python 文件，0 失败。

### D21 异常类型名拼错 —— 错误处理本身会崩

- **症状**：网络异常时不是打印友好提示，而是抛 `AttributeError`。
- **根因**：`urllib.error.HTTPError` 被拼成了别的名字，
  于是 `except` 子句在**异常真正发生时**才崩。
- **影响面**：把"可诊断的错误"变成"看不懂的崩溃"。
- **修法**：改为薄包装器，实际实现只保留一份，并修正名称。
- **位置**：`tools/cf_deploy.py`（薄包装器）
- **验证**：静态检查代码行（**排除注释**）中不再出现该拼写。
  > 注意：文档/注释里会出现这个拼写用于说明历史问题，检查时必须跳过注释。

### D22 节点清单只填了一部分也放行 —— 订阅混入无效地址

- **症状**：订阅里出现不可用节点，客户端连不上其中若干条。
- **根因**：注入逻辑只判断"是否一个都没填"，**部分填充会被放过**，
  残留的 `${NODE_xx_IP}` 占位符直接进了产物。
- **影响面**：用户拿到"看起来正常、实际一半不通"的订阅。
- **修法**：注入后**重新扫描残留占位符**，只要还有就中止并**列出缺失项**。
- **位置**：`deploy/step2_deploy_edge.py`（残留检测段）
- **验证**：构造"部分填充"的输入，断言脚本中止且输出缺失清单。

### D23 改了 `.env` 却不生效 —— 远端绑定永不更新

- **症状**：改了域名/密钥重新部署，线上仍是旧值。
- **根因**：绑定合并逻辑只在"远端没有该绑定"时才写入；
  远端已有同名绑定时**永不更新**。
- **影响面**：配置改动无法上线，且没有任何提示。
- **修法**：明确三条规则 ——
  本地有值 → **覆盖**远端；本地无值 → **保留**远端（绝不写空值抹掉）；
  缺必填 → 中止。
- **位置**：`deploy/step2_deploy_edge.py`（绑定合并段）
- **验证**：三个场景各跑一次，断言覆盖/保留/中止行为正确。

### D24 README 命令与实际路径不符

- **症状**：照 README 敲命令报"文件不存在"。
- **根因**：文档里的命令指向了已经改名的脚本/目录。
- **修法**：逐条核对 README 提到的路径是否存在；删除过时命令。
- **位置**：`README.md`
- **验证**：解析 README 里的命令参数，逐个断言文件存在。

### D25 根目录放了一个"必然失败"的一键入口

- **症状**：根目录的一键脚本执行到某步报找不到步骤脚本。
- **根因**：该脚本被复制到了仓库根目录，但它用相对路径定位步骤脚本，
  而步骤脚本在 `deploy/` 下 —— 复制过去就找不到。
- **修法**：只保留 `deploy/一键.py`，根目录不再放副本。
- **位置**：仓库根（已移除）
- **验证**：断言根目录不存在该文件，且 `deploy/` 下存在。

### D26 一键菜单引用公开仓库里**不存在**的文件

- **症状**：某个菜单项一选就报错。
- **根因**：菜单里的步骤引用了只在私有环境存在的脚本。
- **修法**：移除这些步骤与对应分支，精简菜单。
- **位置**：`deploy/一键.py`
- **验证**：**排除注释**后断言不再引用这些文件名。

### B27 `[新增]` 节点侧脚本被放错目录 —— 同步永不执行

- **症状**：用户库同步"看起来配好了"，但设备上从不执行，也**不报错**。
- **根因**：该脚本被节点脚本以绝对路径调用，
  但部署时被归到了 `tools/`（本地工具目录），**不在推送到设备的清单里**。
- **影响面**：静默失效 —— 最难发现的一类。
- **修法**：移到节点脚本目录，使部署流程会把它推到设备上。
- **位置**：`phone/scripts/sync_worker.sh`
- **验证**：断言它在节点脚本目录、不在 `tools/`，且调用方确实引用了它。

### B28 `[新增]` 推送后没有可执行权限

- **症状**：新设备上守护进程启动失败；老设备因为手工设过权限而看不出来。
- **根因**：推送工具**不保证带可执行位**，而启动脚本是**直接执行**该文件
  （不经过 `sh`），部署流程里也没有 `chmod`。
- **修法**：推送后统一 `chmod 755`，并用 `test -x` **复查**；
  有任一不可执行就中止，不继续重启。
- **位置**：`deploy/step3_deploy_node.py`（权限段）
- **验证**：断言 `chmod` 与复查逻辑存在且能中止。

## 5. 脱敏流程自身引入的缺陷

这一节单独列出，因为它的特点是：**症状出现在产物里，根因在导出工具里**，
而且往往能通过语法检查。

### X29 关键词替换误伤正常单词

- **症状**：节点脚本里 `echo "MISSING: $f"` 被改成了 `echo "MISPOP2G: $f"`。
- **根因**：三字母机房码用**无边界**替换，`SIN` 命中了 `misSINg`。
  同类还有 `CAN` 会命中 `CANnot` 等。
- **影响面**：**静默改坏字符串** —— 不报错，但行为变了（提示信息错乱，
  严重时改坏变量名或命令）。
- **修法**：改为按**独立单词**匹配。注意不能用 `\b`：
  在 Unicode 下 `\b` 遇到中文会失效，要用显式环视：
  ```python
  re.compile(r'(?<![A-Za-z])%s(?![A-Za-z])' % code)
  ```
- **位置**：导出工具（关键词替换表）
- **验证**：改完后**重新统计替换次数**，确认没有"少替换"；
  并单独断言 `MISSING` 这类正常单词未被破坏。

### X30 `[新增]` 自引用占位符 —— 值变成占位符自己的名字

- **症状**：时区配置被求值成字符串 `"DAY_TZ"`；日期格式化拿到无效时区。
- **根因**：脱敏把 `'Asia/Shanghai'` 换成了 `'${DAY_TZ}'`，
  在 JS 模板字符串里 `${DAY_TZ}` 会**引用同名变量自己** —— 自引用。
- **修法**：定义处**整行重写**（用通用正则匹配整行，不依赖具体形态），
  并断言"代码行里不再有裸占位符"。
- **位置**：导出工具的修复流程
- **验证**：断言 `_dayTz()` 定义存在、使用点全部改成调用、
  代码行残留为 0。

### X31 重复赋值 —— 前一处配置被后一处写死值覆盖

- **症状**：样例脚本里同一个变量被赋值两次，后者是写死值，
  于是前面"从配置读"的改动**完全失效**。
- **根因**：改写脚本时按"第一个赋值点"截断，把后面的旧赋值段原样保留了。
- **修法**：删掉重复段，只保留读配置的赋值。
- **验证**：断言每个变量**只出现一次**赋值。

### X32 `[新增]` 遗留脚本会注入**假数据**

- **症状**：该脚本往 Worker 里写"看起来合理"的兜底数值
  （假时延、假电量、假 WiFi 名、假在线时长）。
- **根因**：早期为了让大屏"不空"，刻意加了假兜底；后来正式代码已改成
  "缺就显示未测到"，但这个一次性迁移脚本仍留在仓库里，
  既跑不通（匹配的旧代码已不存在）又是个**错误示范**。
- **影响面**：谁照着它做，就会把假数据引入系统。
- **修法**：从公开产物中**移除**该脚本，并在注释里写明移除原因。
- **验证**：断言该文件不在产物中。

## 8. 一句话总结：哪些写法还会再踩

1. **顶层读 `env`** → 必崩。运行期配置一律走读取器。
2. **在 `_CFG` 之前调用 `_cfg()`** → TDZ。用惰性函数。
3. **模板字符串的注释里写 `${...}`** → 照样求值。要转义。
4. **用"去掉后缀"推断运行文件名** → 迟早对不上。用显式映射表。
5. **失败后仍推进游标/版本号** → 静默不一致。失败必须阻断。
6. **短关键词无边界替换** → 误伤正常单词。用环视断言。
7. **`node --check` 通过就以为能跑** → 加载期与运行期错误它抓不到。
8. **只验管理面** → 代理不通也能全绿。必须验业务链路。

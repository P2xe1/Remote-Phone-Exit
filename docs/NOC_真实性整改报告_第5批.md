## 三、六大地区算法重做（第 87 行）

### 原实现的问题

```sh
PINGS_JSON=""
[ -f "$PING_CACHE" ] && PINGS_JSON=$(cat "$PING_CACHE")
[ -z "$PINGS_JSON" ] && PINGS_JSON="\"pings\":{\"kl\":186,...}"   # ← 编造
```
只要 `ping_cache.txt` 缺失/为空，就把**编造的延迟**当成真实数据上报；
更糟的是假 `pingTimes` 取 `$NOW`，等于**伪装新鲜度**——大屏会显示"刚刚测的"，比不显示危害更大。

### 新算法：三级取材，绝无编造

```
① $PING_CACHE 存在 → 原样透传（调度器刚落盘的最新真实结果）
② 缓存缺失 → 用本地持久化的【上一次真实测量结果】重新组装：
     last_pings.txt(时延) / last_jitters.txt(抖动)
     last_times.txt(真实测量时刻) / last_losses.txt(丢包率)
     → 是历史上真测到的数字, 只是旧一点; pingTimes 用真实时刻,
       大屏如实显示"XX 秒前", 不会伪装成刚刚
③ 连持久化记录都没有(全新设备) → 全部输出 0 = 未测到, 大屏显示 "-- ms"
```

关键点：**0 的语义是"测了但不可达"，不再是"没有数据"**。前端 `setGw()` 与年龄渲染本来就正确处理这两种情况（`0` → `-- ms`；无 `pingTimes` → 红色"未测到"），所以不需要改前端。

真实测量算法本身（未改动，本来就对）：`ping_scheduler.sh` 每区域 **10 次 TCP+TLS 握手（`time_appconnect`）取中位数**，六个区域口径完全一致，丢弃全部失败的采样，**只在测量成功时才更新时间戳** —— 所以年龄是可信的。

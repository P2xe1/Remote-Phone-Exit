01为什么需要它

出口的网络性质，决定了它在各类风控模型里的位置。

出口必须是终端设备的网络地址

数据中心网段在多数风控模型里权重较低；终端设备所在接入网的地址更接近真实用户。

设备在别人家里，必须能自愈

睡眠、断网、进程被杀是常态。节点侧全部采集进程都要能自动恢复，不需要人工介入。

接入面不能暴露固定入口

借任播边缘就近接入 + HTTPS 外观，源站入口由反向隧道建立，免公网入口、免证书轮换。

上行带宽有限，必须精打细算

所有探测与心跳共享同一条终端上行链路，探测并发有硬性上限，能合并的上报必须合并。

02怎么工作

节点只出不进；边缘只做搬运与聚合，看不到加密内容。

客户端 ──HTTPS/443（VLESS + XHTTP + TLS）──▶ 任播边缘 ──反向隧道──▶ 出口节点 ──▶ 目标
   │                                            │                         │
   │                                            │  订阅分发 / 遥测聚合     │  代理核心
   │                                            │  运营监控台（单文件）    │  采集脚本
   └──────────  节点侧约每 6 秒上报一次遥测  ◀────┘                         │
                                                                          ▼
                                                              分段实测：客户端接入 / 边缘 /
                                                              隧道 / 节点设备 / 出口网络
  • 节点只发出站连接 —— 不监听端口、不需要公网 IP、不需要端口映射，因此在 NAT、CGNAT 与移动网络下同样可用。
  • 边缘负责分发与聚合 —— 订阅配置、遥测聚合、跨接入点快照与监控台渲染。
  • 节点负责出口与测量 —— 代理核心转发，全部采集脚本负责把每一段的真实值量出来。
  • 观测面不参与推导 —— 监控台只渲染快照，不各算一套，避免"同一个人在不同接入点显示不同结果"。

03你能得到什么

功能与观测口径，均以"可实测、可回溯"为准。

订阅分发

同一用户库输出 Clash / v2ray 两种格式，支持统一时延口径。

分段时延遥测

五段分别实测量化，可归因到具体分段，而不是只给一个端到端数字。

会话状态跟踪

以代理核心的活动连接清单为权威，输出在线 / 会话已终止 / 长期无会话 / 无会话记录。

流量计量

逐用户上下行累计（单调不减）+ 15 分钟与当日带宽峰值。

中继节点矩阵

节点逐个巡检，逐节点输出可达性与 RTT，正常周期内不误报数据老化。

运营监控台

单文件前端，含带宽示波器、域名访问排行、节点矩阵与用户会话状态。

  • 观测口径纪律 —— 任何一个对外呈现的数字，都必须能回答"由谁、在什么时刻、以什么方式测得"。
  • 缺测就显示空值 （不推测） —— 无法测量时输出 --，绝不用推测值填补。
  • 计量不可逆 —— 逐用户累计流量单调不减，基线重置时按增量补偿。

04快速开始

边缘一条命令部署；节点侧脚本按固定顺序启动。

# 1) 准备配置（凭据只放本地，不进版本库）
cp .env.example .env

# 2) 自检 + 分步部署
python deploy/一键.py
python tools/cf_deploy.py

# 3) 节点侧：按固定顺序启动（守护进程 → 上报调度 → 采集脚本）
sh run_daemon.sh

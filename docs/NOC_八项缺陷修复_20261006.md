## 1. 逐条修复

### 缺陷 1 · 后台删除的默认用户被节点回推"复活"

| 项 | 内容 |
| --- | --- |
| 位置 | 边缘 Worker，用户库回推接口（`/api/phone_users` 的 POST 分支） |
| 根因 | 判定条件写反：注释明确"带版本的载荷（节点回推）是权威视图，直接采用；只有裸对象才合并默认名单"，但代码写成 `wrapped \|\| 空` 才走合并 —— 节点正常回推时必然命中该分支，于是被删除的默认成员又被合并回来 |
| 修法 | 条件改为 `!wrapped \|\| 空`：裸对象（旧客户端/手工恢复）与空载荷才合并默认名单；带版本的节点回推一律以其为准 |
| 验证 | ① 后台删除一个默认用户；② 在节点上执行一次同步（触发回推 + 配置拉取）；③ 确认该用户**没有**被写回（后台列表、用户库、节点配置三处一致） |

### 缺陷 2 · 任意 ≥6 字符 token 可免鉴权拉取全部节点配置

| 项 | 内容 |
| --- | --- |
| 位置 | 边缘 Worker，订阅下发（`/sub`） |
| 根因 | 为防"冷机房缓存未同步误伤正常用户"，原实现允许**任何 ≥6 字符**的未知 token 以临时对象身份通过，等于把全部节点配置（地址/端口/凭据/分流路径）向任意随机字符串开放；已删除的用户同样能继续拉取 |
| 修法 | 改为**二次权威核验**：先走原有四级查询（本实例内存 → 本机房缓存 → 全局存储 → 兜底名单）；仍未命中时**直查一次全局权威用户库**，确认不存在一律返回 403。临时对象路径整段删除 |
| 验证 | ① `curl` 请求随机 token → 期望 **403**；② 用真实 token 请求 → 期望 **200** 且配置正常 |
| 额度影响 | 只增加**读**（每次未知 token 请求一次，且全局库读取默认带 60 秒缓存）；**不产生写入** |

### 缺陷 3 · 探测名额的并发竞态与提前误删

| 项 | 内容 |
| --- | --- |
| 位置 | 节点脚本 `probe_gate.sh`（名额回收逻辑） |
| 根因 | 回收条件写成"pid 为空 **或** 进程不存在"。进程刚 `mkdir` 成功、还没把 pid 写进文件的**微秒级窗口**内，另一个进程会读到空 pid 并立刻删除该名额目录 —— 并发上限 2 失效 |
| 修法 | pid 为空时**不再立刻回收**：只有"目录已存在 ≥3 秒且仍然没有存活 PID"才判定为残留并回收；pid 非空时仍按"进程是否存活"判断 |
| 验证 | 设备侧单测（独立测试目录，8 项断言全通过）：新鲜无名额不被误删 / 陈旧残留被回收 / 已死持有者被回收 / 存活持有者不被抢占 |
| 备注 | 时间戳取自 `stat -c %Y`，已在本项目目标设备（Android，Toybox）实测可用 |

### 缺陷 4 · 峰值字段在多数上报轮次缺失

| 项 | 内容 |
| --- | --- |
| 位置 | 节点脚本 `report_traffic.sh`（带宽峰值段落） |
| 根因 | 该脚本每约 6 秒被调度一次、执行完即退出；峰值计算挂在"每 30 秒重算"分支里，中间那几轮变量为空，载荷里就整个缺少峰值字段 |
| 修法 | ① 峰值落盘时把 15 分钟峰值一并写入（原来只写"日峰值 + 日期"）；② 非重算周期从该文件复用最新峰值填充字段；③ 老格式文件（只有两个字段）按"15 分钟峰值 = 0"兼容；④ 无文件时保持为空，不编造数字 |
| 验证 | 设备侧单测（4 项全通过）：新格式三字段正确 / 旧格式兼容 / 无文件不编造 / 已有值不被覆盖 |

### 缺陷 5 · 精简快照缺字段导致三项指标卡 60 秒

| 项 | 内容 |
| --- | --- |
| 位置 | 边缘 Worker：上报处理（快照组装）、精简快照生成函数、监控台前端带宽面板 |
| 根因 | "总计上下行流量 / 15 分钟峰值 / 一天峰值"依赖的用户累计字节与峰值字段只存在于完整统计接口（60 秒一次），精简推送里没有；前端只能等下一次整页轮询，表现为"半圆仪表在跳、下面三项卡住" |
| 修法 | ① 上报处理里按既有口径（逐用户累计值求和，**不新造数字**）把总计上下行写入快照；② 精简快照补出峰值与两项总计；③ 前端在推送回调里把该快照传给带宽面板，并在字段缺失时回退到最近一次完整统计（而不是显示 0） |
| 验证 | 打开监控台，产生流量或手动触发探测，确认"总计上下行流量 / 15 分钟峰值 / 一天峰值"随推送周期（约 5–6 秒）刷新，不再需要等 60 秒 |

### 缺陷 6 · 审计脚本断言过时

| 项 | 内容 |
| --- | --- |
| 位置 | 审计脚本 `full_audit.py`（Clash 订阅检查段） |
| 根因 | 订阅分组已按用户决策精简为「代理 / 自动优选 / 故障转移」三组，专线与地区组全部删除；脚本仍在断言旧分组存在，导致检查在第 2 步直接抛断言错误 |
| 修法 | 删除对已废弃分组的断言与打印项，保留三组核心断言与节点数量断言 |
| 验证 | 运行审计脚本，第 1、2 步通过（订阅含三组核心分组、节点数达标） |
| 备注 | 第 3 步另有一条**同类过时断言**（检查 5 个区域网关 DOM 元素，而该 UI 区块已按用户要求从大屏移除）—— **该条不在本次修复清单内，已单独报请确认后再动** |

### 缺陷 7 · 长轮询等待期重复回源全局快照

| 项 | 内容 |
| --- | --- |
| 位置 | 边缘 Worker：精简快照生成函数 + 长轮询循环 |
| 根因 | 长轮询每 1 秒重读一次快照，若本机房缓存陈旧，每一轮都会回源全局存储 |
| 修法 | 为快照生成函数增加"是否允许回源"参数；长轮询**仅首轮**允许回源，其后只读本机房缓存与内存（节点一旦有新上报，第一时间写入的正是本机房缓存） |
| 实现说明 | 报告给出的补丁写作 `readLiveSnapshot(first)`，但该变量在调用前已被置为 false —— 照抄会导致**回源彻底失效**（冷机房的兜底链断掉）。本次按原意修正为：先取出首轮标志再复位，然后按标志调用 |
| 验证 | 冷机房场景下长轮询仍能拿到全局快照（首轮生效）；同一次长轮询的后续等待轮次不再产生存储读 |

### 缺陷 8 · 重启脚本杀进程顺序与设计冲突

| 项 | 内容 |
| --- | --- |
| 位置 | 节点脚本 `run_daemon.sh`（重启前的进程清理段） |
| 根因 | 注释写明"先杀看门狗（否则它不断复活子进程），再杀其余"，实际代码先杀核心进程 —— 在"核心已死、看门狗还活着"的窗口里，看门狗会用旧配置把核心拉起来 |
| 修法 | 严格按注释顺序：先停守护/调度进程，再停隧道客户端与代理核心 |
| 验证 | 设备侧重启脚本语法检查通过；下一次完整重启时观察进程列表，不再出现"旧进程被复活/双份进程" |

## 3. 存储额度影响（免费额度 1000 次写入/天）

| 改动 | 写入影响 | 读取影响 |
| --- | --- | --- |
| 缺陷 1 用户库合并判定 | 无 | 无 |
| 缺陷 2 订阅鉴权二次核验 | **无**（只读全局用户库，且默认带 60 秒缓存） | 未知 token 请求各 +1 次（正常用户不受影响） |
| 缺陷 3/4/8 节点脚本 | 无（不涉及存储） | 无 |
| 缺陷 5 快照补字段 | **无**（沿用原有快照写入，字段是顺带带上的） | 无 |
| 缺陷 6 审计脚本 | 无 | 无 |
| 缺陷 7 长轮询限制回源 | 无 | **减少**（等待期不再重复回源） |

> 结论：本次改动**不增加任何写入**；全局快照的单写者机制（含当日硬上限 900 次）保持原样。
> 现场核对方式：管理员接口 `/api/kv_health` 会给出「快照年龄 / 当日写入次数 / 当前写入接入点 / 当日上限」。
